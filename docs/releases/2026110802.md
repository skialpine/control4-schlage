# 2026110802 — Composer Properties fix

This update fixes startup timing that could leave Composer showing “Not
retrieved” or “Waiting for sign in” after the account had already connected and
found your locks. Properties stayed correct during testing after this update.
Lock, unlock, and status updates in the Control4 app also passed.

## What changed

- Corrected how both drivers publish their Properties after starting or
  updating.
- Prevented startup values and responses from an old session from overwriting
  current discovery and polling results.
- Included the template updates from 2026110801: a fix for renaming shared
  connections, smaller driver packages, and logging adjustments to keep raw
  traffic dumps disabled while retaining filtered Ultra logs.

## Updating

In **Schlage Account**, select **Update Channel → Stable**, then run **Actions →
Check for Updates**. Both Schlage drivers should show version **2026110802**
afterward. Saved credentials, lock selections, and connections are kept during
the update.

Already running 2026110802? You have these fixes and do not need to reinstall.

For a manual update, download both `.c4z` files and import them through
Composer's **Add or Update Driver**. Let Composer manage its Drivers folder; do
not overwrite files there yourself.

If Composer still shows old values, restart Composer and reconnect. If new
settings are missing, synchronize the driver definition from the controller
through **Manage Drivers**.

## Testing and remaining checks

Post-update Properties, lock, unlock, and app status updates passed. Automated
tests also passed for sign-in, discovery, command handling, notifications, and
driver reloads. Outage recovery and scheduled daily low-battery reminders still
need hardware testing. The **Test Battery Alert** notification has been checked
on CORE5.

This is the stable release. Its original GitHub tag, `v2026110802-beta.1`,
remains in place so everyone receives the same tested files.
