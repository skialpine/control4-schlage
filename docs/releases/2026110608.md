# Initial stable release — 2026110608

Native Schlage Home account and lock drivers for Control4, with no Home Assistant
runtime dependency. This release promotes the tested 2026110607 runtime with a
new package version and updated documentation; it adds no new lock commands or
authentication changes.

## Included

- Direct Schlage Home sign-in, encrypted credential/session persistence, token
  renewal, and discovery.
- One Schlage Lock companion per physical lock, with account/lock dropdowns and
  support for multiple locks in the same or different rooms.
- Native Lock, Unlock, and Toggle through a bound generic Control4 Door Lock,
  with reported bolt state, availability, battery, and command outcomes.
- Bounded command confirmation and queue handling, programming events and
  conditions, local diagnostics, and redacted logging.
- Account-wide optional daily low-battery push notifications, a separate Composer
  event, configurable local alert time/threshold, and a labeled TEST action.
  Messages prefer the visible Control4 Door Lock name.
- GitHub automatic updates on Stable or Prerelease channels, plus manual checks.
  Properties timestamps use controller local time.

## Installation and upgrade

Download both `schlage_account.c4z` and `schlage_lock.c4z`, or the
`control4-schlage.zip` bundle containing both drivers and documentation PDFs.
Minimum declared Control4 OS is 3.4.1.

Existing updater-enabled installations can run **Schlage Account → Actions →
Check for Updates** on either channel. Both drivers should report **2026110608**.
Select **Stable** to exclude future prereleases. Preserve account credentials,
physical-lock selections, and generic Door Lock relay bindings.

For manual installation, use Composer's **Add or Update Driver**. If Composer
shows an old Properties layout after a controller update, synchronize/import the
current definition through Composer. Do not externally copy packages into
Composer's Drivers directory. Save a project backup before commissioning.

For each physical lock, add a Schlage Lock companion, select its account/lock,
and connect a generic **Door Lock** relay input to its **Lock State** output.
The generic Door Lock supplies the Navigator tile. Refresh Navigators afterward.

## Validation and limitations

Local release checks passed: 54 Lua suites with 2,312 assertions, 51 Python
tests, formatting/static checks, strict OpenSpec validation, package versions,
and generated PDFs. Both packaged Lua scripts match the published 2026110607
runtime exactly.

Live user testing covers CORE1 / OS 3.4.3 and CORE5 / OS 4.3 with two Schlage
Encode Plus BE499WB locks: lock/unlock, matching state, external state updates,
independent lock routing, battery reporting, session recovery, and prior GitHub
updates. CORE5 TEST push delivery and the visible Control4 name also passed.
Other lock models and firmware combinations are not established by this testing.

Network outage/recovery acceptance is **deferred at the user's request**.
Scheduled daily alert suppression, next-day reminders, and modification of an
existing notification message have local tests but remain unverified on hardware.
Rapid command handling and jam/fault behavior also have local regression coverage;
no physical jam test is claimed.

This driver requires Schlage's cloud and internet connectivity. Cloud command
acceptance does not confirm the physical bolt; feedback can take several seconds,
and manual changes depend on polling. PIN management, advanced lock options,
schedules, history, and local/offline lock control are not implemented. Allegion
partner OAuth integration is on hold and is not part of this release.
